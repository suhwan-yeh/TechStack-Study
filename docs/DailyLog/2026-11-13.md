## 오늘 학습·정리한 내용

### 1. EC2 DB 개인 계정과 IP 접근 설정
- 팀원별 MySQL 계정을 만들어도 네트워크 접근이 허용되지 않으면 외부에서 접속할 수 없다.
- DB 계정·권한은 “누가 어떤 데이터를 사용할 수 있는지”를 관리한다.
- EC2 보안 그룹은 “어느 IP에서 어떤 포트로 접속할 수 있는지”를 관리한다.
- 기존 접속 실패 원인은 MySQL 접속용 보안 그룹이 EC2에 연결되지 않은 것이었다.
- 학원 공인 IP의 TCP 3306 접근을 허용하고 보안 그룹을 EC2에 연결한 뒤 팀원 접속에 성공했다.
- 접속 장소나 공인 IP가 바뀌면 허용 IP를 다시 확인해야 한다.

※ 계정 생성·접속 문제 해결은 11월 12일 작업이며, 오늘은 원인과 해결 과정을 복습했다.

### 2. Nginx의 개념과 장점
- Nginx는 웹서버이며, 사용자 요청을 앱으로 전달하는 리버스 프록시로도 사용한다.
- CRM에 적용하면 사용자 → Nginx → 내장 Tomcat(8082) 구조로 구성할 수 있다.
- 주요 장점:
  - HTTPS 인증서와 접속 설정을 앱과 별도로 관리
  - 이미지·CSS·JavaScript 같은 정적 파일 제공
  - 여러 앱으로 요청 분기 또는 여러 서버에 부하 분산
  - 요청 크기·횟수·시간 제한
- Nginx는 필수가 아니며 내장 Tomcat도 직접 HTTPS를 처리할 수 있다.
- 기본 포트인 HTTP 80 또는 HTTPS 443을 사용하면 주소에서 포트번호를 생략할 수 있다.
- Nginx 설치만으로 HTTPS가 적용되지는 않으며 인증서 설정이 필요하다.

### 3. SSH의 개념
- SSH는 암호화된 통신으로 원격 서버에 접속하고 명령을 실행하는 프로토콜이다.
- 현재 프로젝트에서는 내 PC의 PowerShell에서 EC2 Ubuntu 서버에 접속할 때 사용한다.
- SSH 기본 포트는 22이며, 보안 그룹의 접근 허용과 로그인 인증이 모두 필요하다.
- 개인키는 로그인 자격을 증명하고, 서버 공개키는 접속 대상 서버의 신원을 확인하는 데 사용한다.
- CD에서는 GitHub Actions가 SSH로 EC2에 접속해 배포 명령을 실행한다.

### 4. 브라우저 개발자 도구의 Network 디버깅
- F12로 개발자 도구를 열고 Network 탭에서 브라우저의 요청과 응답을 확인한다.
- Network 탭을 연 상태에서 새로고침하거나 문제 동작을 재현한다.
- Fetch/XHR 필터를 사용하면 API 요청을 중심으로 확인할 수 있다.

| 확인 항목 | 확인 목적 |
|---|---|
| Request URL / Method | 올바른 주소와 GET·POST 등의 방식으로 요청했는지 확인 |
| Status | 응답 상태 코드 확인 |
| Headers | 요청·응답 헤더와 인증 정보 전달 여부 확인 |
| Payload | 서버에 보낸 데이터 확인 |
| Response / Preview | 서버가 반환한 데이터·오류 내용 확인 |
| Timing | 응답이 지연되는 구간 확인 |

- Network 정보로 문제 범위를 좁힌 뒤 서버 로그와 함께 원인을 분석한다.
- 상태 코드만으로 정확한 원인을 단정하지 않는다.
- 캡처나 로그 공유 시 토큰·쿠키·비밀번호 등은 가린다.

### 5. HTTP 상태 코드 분류
- HTTP 상태 코드는 오류만 나타내는 것이 아니라 요청 처리 결과를 나타낸다.

| 분류 | 의미 | 대표 예시 |
|---|---|---|
| 1xx | 요청 처리 중의 정보성 응답 | 100 Continue |
| 2xx | 요청이 성공적으로 처리됨 | 200 OK, 201 Created, 204 No Content |
| 3xx | 리디렉션 또는 캐시 관련 추가 처리 | 301·302 이동, 304 캐시 재사용 |
| 4xx | 요청·인증·권한·대상 등의 문제 | 400 잘못된 요청, 401 인증 필요, 403 접근 거부, 404 대상 없음 |
| 5xx | 서버가 요청을 처리하지 못함 | 500 서버 내부 오류, 502 게이트웨이 오류, 503 서비스 이용 불가 |

- 4xx라고 해서 반드시 사용자의 실수라는 뜻은 아니다.
- 로그인 화면의 HTTP 200은 화면 응답 성공을 의미하며, 실제 로그인 성공까지 보장하지 않는다.
