## 1. API와 REST API

### API란?

API(Application Programming Interface)는 프로그램 사이에서 기능이나 데이터를 주고받기 위한 약속 또는 인터페이스다.

예를 들어 여행지 서비스를 만든다면:

```text
사용자 브라우저
  ↓ 여행지 목록 요청
서버 API
  ↓ 데이터 조회
DB 또는 외부 관광 API
  ↓ 결과 반환
서버
  ↓ JSON 응답
사용자 브라우저
```

**API가 반드시 웹 API인 것은 아니다.** 라이브러리의 메서드도 API에 포함된다.

### REST API란?

REST는 웹에서 자원을 다루는 아키텍처 스타일이다. 흔히 REST API라고 부르는 HTTP API에서는 URL로 자원을 표현하고 HTTP 메서드로 작업을 구분한다.

```http
GET /articles/10
```

- `/articles/10`: 10번 게시글이라는 자원
- `GET`: 조회 작업

**기억할 것:** API는 더 넓은 개념이고, REST API는 REST 원칙을 따르도록 설계한 API다. JSON을 사용한다고 자동으로 REST API가 되는 것은 아니다.

## 2. REST API 설계 규칙

### URL은 자원을 표현

```text
GET    /articles        게시글 목록 조회
GET    /articles/10     10번 게시글 조회
POST   /articles        게시글 생성
PUT    /articles/10     10번 게시글 전체 교체
PATCH  /articles/10     10번 게시글 일부 수정
DELETE /articles/10     10번 게시글 삭제
```

보통 URL에는 동사보다 명사를 사용하고, 어떤 동작인지는 HTTP 메서드로 구분한다.

### 주요 HTTP 메서드

| 메서드 | 대표 용도 | 특징 |
|---|---|---|
| GET | 조회 | 서버 자원 변경을 의도하지 않음 |
| POST | 생성·처리 요청 | 요청에 따라 새로운 자원 생성 가능 |
| PUT | 전체 교체 | 같은 요청 반복 시 결과가 같도록 설계 |
| PATCH | 부분 수정 | 일부 필드만 변경 |
| DELETE | 삭제 | 같은 요청 반복 시 최종 상태가 같도록 설계 |

### HTTP 상태 코드

| 코드 | 의미 | 예시 |
|---|---|---|
| 200 OK | 요청 성공 | 게시글 조회 성공 |
| 201 Created | 자원 생성 성공 | 게시글 생성 성공 |
| 204 No Content | 성공, 응답 본문 없음 | 삭제 성공 |
| 400 Bad Request | 잘못된 요청 | 필수 입력값 누락 |
| 401 Unauthorized | 인증 필요 또는 실패 | 로그인하지 않음 |
| 403 Forbidden | 접근 권한 없음 | 다른 사람의 관리자 기능 접근 |
| 404 Not Found | 자원을 찾을 수 없음 | 없는 게시글 번호 |
| 500 Internal Server Error | 서버 내부 오류 | 처리 중 예기치 않은 예외 |

> `401`은 이름과 달리 주로 **인증** 문제이고, `403`은 **권한** 문제다.

### JSON 응답 예시

```json
{
  "id": 10,
  "title": "Spring Boot 공부",
  "author": "홍길동"
}
```

JSON은 서버와 클라이언트 사이에서 구조화된 데이터를 교환할 때 자주 사용하는 형식이다.

## 3. Spring Boot 프로젝트 준비

### Spring Boot란?

Spring Boot는 Spring 애플리케이션을 빠르게 설정하고 실행하도록 돕는다. Spring 자체나 Java 언어, JPA와 같은 뜻은 아니다.

### 의존성이란?

프로젝트가 특정 기능을 사용하기 위해 필요한 라이브러리다.

예를 들어 다음 의존성을 사용할 수 있다.

- Spring Web: HTTP 요청 처리 및 REST 컨트롤러
- Spring Data JPA: Repository 기반 데이터 접근
- H2 Database: 학습·테스트용으로 자주 사용하는 관계형 DB
- Lombok: Getter, 생성자 등 반복 코드 생성 지원

Gradle 프로젝트에서는 보통 `build.gradle`에서 의존성을 관리한다.

### application.yml

```yaml
spring:
  datasource:
    url: jdbc:h2:mem:testdb
    driver-class-name: org.h2.Driver
    username: sa
    password:
  h2:
    console:
      enabled: true
  jpa:
    hibernate:
      ddl-auto: create
    show-sql: true
```

이것은 **학습용 H2 인메모리 DB 설정 예시**다. `ddl-auto: create`는 시작할 때 스키마를 다시 생성할 수 있으므로 운영 환경에 그대로 사용하면 위험하다. 실제 H2 콘솔 경로, 접속 정보, SQL 초기화 동작은 프로젝트 설정에 따라 달라진다.

### H2 콘솔이란?

H2 데이터베이스의 테이블과 데이터를 웹 화면에서 조회하고 SQL을 실행할 수 있는 도구다. 콘솔을 활성화한 경우 기본 경로는 일반적으로 `/h2-console`이다.

## 4. ORM과 Entity

### ORM이란?

ORM(Object-Relational Mapping)은 **객체와 관계형 데이터베이스의 테이블을 연결하는 기술**이다.

```text
Java 객체 Member         DB 테이블 member
----------------        -----------------
id: 1                    id | name
name: 홍길동              1 | 홍길동
```

JDBC 방식에서는 SQL 작성과 결과 변환을 개발자가 직접 처리하는 경우가 많다. ORM을 사용하면 객체 중심으로 데이터에 접근하고 매핑 작업을 줄일 수 있다. 다만 SQL과 DB 구조를 몰라도 된다는 뜻은 아니다.

### Entity란?

JPA가 관리할 수 있는 영속 객체를 나타내는 클래스다. 보통 DB 테이블에 매핑된다.

```java
import jakarta.persistence.*;
import lombok.AccessLevel;
import lombok.Getter;
import lombok.NoArgsConstructor;

@Entity
@Getter
@NoArgsConstructor(access = AccessLevel.PROTECTED)
public class Member {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    @Column(name = "id", updatable = false)
    private Long id;

    @Column(name = "name", nullable = false)
    private String name;

    public Member(String name) {
        this.name = name;
    }
}
```

- `@Entity`: JPA 엔티티로 지정
- `@Id`: 기본키 필드 지정
- `@GeneratedValue`: 기본키 생성 방식 설정
- `GenerationType.IDENTITY`: DB의 ID 생성 기능 활용
- `@Column`: 컬럼명, NULL 허용 여부 등의 매핑 설정
- `@Getter`: Lombok이 Getter 생성
- `@NoArgsConstructor(PROTECTED)`: JPA가 사용할 수 있는 기본 생성자 생성

**주의:** `@Entity`를 붙였다고 언제나 자동으로 테이블이 생성되는 것은 아니다. 실제 생성 여부는 JPA 스키마 설정에 달려 있다. `PROTECTED` 생성자는 같은 패키지 및 하위 클래스에서 접근할 수 있다.

## 5. JPA, Hibernate, Spring Data JPA

| 기술 | 정체 | 핵심 역할 |
|---|---|---|
| JPA | Java ORM 표준 명세 | 엔티티와 영속성 관리 API 정의 |
| Hibernate | 대표적인 JPA 구현체 | 매핑·SQL 생성·영속성 관리 구현 |
| Spring Data JPA | Spring Data 모듈 | Repository 사용을 간편하게 만듦 |
| Spring Boot | Spring 애플리케이션 실행·설정 지원 | 자동 설정과 개발 편의 제공 |

```text
Spring Boot 애플리케이션
        ↓
Spring Data JPA (JpaRepository)
        ↓
JPA API (EntityManager)
        ↓
Hibernate (대표 구현체)
        ↓
JDBC / 데이터베이스
```

이것은 흔히 사용하는 구성 예시다. Spring Boot 없이 JPA를 사용할 수도 있고, Spring Boot에서 JPA 대신 JDBC나 MyBatis를 사용할 수도 있다.

### EntityManager와 Repository 비교

JPA의 `EntityManager`를 직접 사용하면:

```java
Member member = em.find(Member.class, 1L);
```

Spring Data JPA의 Repository를 사용하면:

```java
public interface MemberRepository
        extends JpaRepository<Member, Long> {
}

// 호출하는 쪽
Optional<Member> member = memberRepository.findById(1L);
```

`JpaRepository<Member, Long>`에서 `Member`는 엔티티 타입, `Long`은 기본키 타입이다.

**기억할 것:** `JpaRepository`는 JPA 표준이 아니라 Spring Data JPA가 제공하는 인터페이스다.

## 6. EntityManager와 영속성 컨텍스트

### EntityManager란?

JPA 엔티티를 저장, 조회, 삭제하고 영속성 컨텍스트를 다루는 API다.

```java
em.persist(member);              // 영속 상태로 관리 시작
em.find(Member.class, 1L);       // PK 조회
em.remove(member);               // 삭제 예약
em.flush();                      // DB와 동기화
```

### 영속성 컨텍스트란?

**엔티티를 관리하고 변경을 추적하는 JPA의 관리 영역**이다.

```text
Java 애플리케이션
        ↓
EntityManager
        ↓
영속성 컨텍스트
  ├─ 1차 캐시
  ├─ 변경 감지(Dirty Checking)
  └─ 쓰기 지연
        ↓ flush
데이터베이스
```

### ① 1차 캐시

```java
Member m1 = em.find(Member.class, 1L);
Member m2 = em.find(Member.class, 1L);
```

같은 영속성 컨텍스트에서 같은 엔티티 ID를 조회하면 일반적으로 같은 관리 객체가 반환된다. 첫 조회는 DB 접근이 필요할 수 있지만 두 번째 조회는 1차 캐시를 사용할 수 있다.

### ② 변경 감지(Dirty Checking)

```java
Member member = em.find(Member.class, 1L);
member.changeName("김철수"); // 변경 메서드가 있다고 가정
```

트랜잭션 안에서 영속 상태의 엔티티가 수정되면 JPA가 변경 내용을 추적하고 flush 시점에 UPDATE를 실행할 수 있다. 위 예시의 `changeName()`은 앞의 Member 코드에는 없는 설명용 메서드다.

### ③ 쓰기 지연과 flush

```java
em.persist(member);
// 상황에 따라 INSERT가 flush 시점까지 지연될 수 있음
em.flush();
```

`flush()`는 영속성 컨텍스트의 변경 내용을 DB에 반영하도록 SQL을 실행하는 과정이며, **트랜잭션 commit과 같은 뜻은 아니다.** 특히 `GenerationType.IDENTITY`에서는 ID를 얻기 위해 INSERT가 `persist()` 시점에 실행될 수 있다.

## 7. 엔티티 상태 4가지

| 상태 | 뜻 | 대표적인 전환 |
|---|---|---|
| 비영속(new/transient) | 객체만 만들고 JPA가 관리하지 않음 | `new Member(...)` |
| 영속(managed) | 영속성 컨텍스트가 관리함 | `persist()`, `find()` |
| 준영속(detached) | 관리되다가 분리됨 | `detach()`, `clear()`, `close()` |
| 삭제(removed) | DB 삭제 대상으로 예약됨 | `remove()` |

### 비영속 → 영속

```java
Member member = new Member("홍길동"); // 비영속
em.persist(member);                   // 영속
```

### 영속 → 준영속

```java
Member member = em.find(Member.class, 1L);
em.detach(member);
// 이후 member를 수정해도 자동 변경 감지 대상이 아님
```

### 준영속 → 영속 객체 얻기

```java
Member managedMember = em.merge(member);
```

`merge()`는 전달한 객체 자체를 다시 영속 상태로 만드는 것이 아니라 **상태를 복사한 관리 객체를 반환**한다. 이후에는 반환된 객체를 사용해야 한다.

### 영속 → 삭제

```java
Member member = em.find(Member.class, 1L);
em.remove(member);
```

삭제 SQL은 flush 시점에 실행될 수 있으며, 최종 확정에는 트랜잭션 commit이 필요하다.

## 8. Spring Data JPA의 JpaRepository

```java
import org.springframework.data.jpa.repository.JpaRepository;

public interface MemberRepository extends JpaRepository<Member, Long> {
}
```

| 메서드 | 기능 |
|---|---|
| `save(member)` | 새 엔티티 저장 또는 기존 엔티티 병합 |
| `findById(1L)` | 기본키로 조회 |
| `findAll()` | 전체 조회 |
| `deleteById(1L)` | 기본키에 해당하는 엔티티 삭제 |

### Optional이란?

```java
Optional<Member> result = memberRepository.findById(1L);
```

조회 결과가 없을 수 있음을 타입으로 표현한다. 없는 데이터를 무조건 `.get()`으로 꺼내면 예외가 발생할 수 있다.

```java
Member member = memberRepository.findById(1L)
    .orElseThrow(() -> new IllegalArgumentException("회원을 찾을 수 없음"));
```

### Repository는 왜 편할까?

기본 CRUD에 필요한 반복 코드를 줄일 수 있다. 하지만 실제 실행 SQL, 트랜잭션, 연관관계, 성능 문제를 이해하는 일은 여전히 중요하다.

## 9. 이전 JSP/Servlet 프로젝트와 연결하기

```text
[이전 JSP/Servlet + JDBC 방식]
브라우저 → Servlet Controller → Service → DAO → JDBC → DB

[Spring Boot + Spring Data JPA 방식]
브라우저 → Spring MVC Controller → Service → Repository
                                             ↓
                                       JPA / Hibernate → DB
```

기존 프로젝트에서는 DAO에서 SQL을 직접 작성했지만, 지금은 Repository를 통해 JPA를 사용할 수 있다는 점이 큰 차이다. 단, Spring Boot에서도 JDBC를 사용할 수 있고 JSP도 함께 사용할 수 있다.

REST API의 경우 JSP 화면을 서버에서 만드는 대신 JSON 데이터를 응답하고, 브라우저의 JavaScript나 별도 프론트엔드가 화면을 구성할 수도 있다.

### 직접 구현해 볼 미니 실습

- `Article` 엔티티를 만들고 `id`, `title`, `content` 필드를 매핑하기
- `ArticleRepository extends JpaRepository<Article, Long>` 작성하기
- `GET /articles/{id}` 조회 API를 만들고 데이터가 없을 때 404 응답하도록 구현하기

## 오늘의 핵심 정리

- **API**: 프로그램 사이의 기능·데이터 교환을 위한 인터페이스
- **REST**: HTTP에서 자원을 중심으로 설계하는 아키텍처 스타일
- **Spring Boot**: Spring 애플리케이션 개발과 실행을 편리하게 하는 도구
- **ORM**: 객체와 관계형 DB 사이의 매핑
- **JPA**: 자바 ORM 표준 명세
- **Hibernate**: 대표적인 JPA 구현체
- **Spring Data JPA**: JPA 기반 Repository를 편하게 사용하는 모듈
- **Entity**: JPA가 관리하는 영속 객체
- **영속성 컨텍스트**: 엔티티 관리, 1차 캐시, 변경 감지 등의 중심
- **JpaRepository**: 기본 CRUD 메서드를 제공하는 Spring Data JPA 인터페이스


**다음 목표: REST API → Controller → Service → Repository → DB 흐름을 직접 구현하고 설명하기.**
