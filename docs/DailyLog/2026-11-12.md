# 2026-11-12 Daily Log

## 오늘의 목표
EC2 MySQL의 팀 공동 접속 환경을 구성하고, 더미 데이터 입력 및 앱·DB 연동을 확인한다.

## 진행한 작업

### 1. 팀원별 MySQL 계정 및 권한 설정
- EC2 MySQL에 팀원별 접속 계정 생성
- 공용 matzip DB에 접근할 수 있도록 권한 부여
- 계정에 REQUIRE SSL을 적용하여 암호화 연결 필수 설정
- 앱용 DB 계정과 팀원 작업용 계정을 분리

### 2. DB 외부 접속 및 Workbench 연결
- MySQL 실행 상태와 3306 포트 연결 대기 확인
- 학원 공인 IP에서만 3306 포트에 접근하도록 보안 그룹 설정
- MySQL 보안 그룹을 EC2 인스턴스에 연결
- Workbench의 SSL 연결 설정 확인
- 본인 및 팀원들의 EC2 DB 접속 성공 확인

### 3. 테스트용 더미 데이터 입력
- 프로시저 없이 INSERT와 트랜잭션을 사용하는 더미 SQL 준비
- 회원·매장·고객·방문·포인트·쿠폰 데이터 입력 완료
- 팀원들이 같은 DB의 데이터를 사용하여 기능을 테스트할 환경 마련

### 4. 앱과 EC2 DB 연동 테스트
- 로컬 앱을 EC2의 matzip DB에 연결
- 앱 기동 및 DB 테이블 구조 검증 통과
- 로그인 화면 HTTP 200 응답 확인
- 프로젝트 이름 crm과 DB 이름 matzip이 달라도, DB_URL이 올바르면 연결에 문제가 없음을 확인

### 5. Google 로그인 오류 분석
- Google 로그인 실패를 재현하고 인증 로그 확인
- Google 응답의 401 invalid_client 오류를 통해 Client Secret 문제 확인
- OAuth Client ID와 Secret의 유효한 조합 확인이 필요함을 정리
- 로그인 성공까지는 미확인

## 발생한 문제와 해결

| 문제 | 원인 | 해결 및 결과 |
|---|---|---|
| Workbench에서 EC2 DB 접속 실패 | MySQL 보안 그룹이 EC2에 연결되지 않음 | 접속 규칙과 보안 그룹 연결을 정리하여 팀원 접속 성공 |
| crm과 matzip 이름 차이로 인한 오류 우려 | 프로젝트 이름과 DB 이름의 역할 혼동 | 실제 DB_URL과 앱 연결을 확인하여 matzip 사용에 문제없음을 확인 |
| Google 로그인 실패 | 유효하지 않은 Client Secret | 로그로 원인 확인, 인증 설정 수정 후 재테스트 필요 |
| EC2 CRM 서비스 실행 실패 | 서버에 crm.jar 파일이 없음 | 서비스 중지 후 CD를 통한 첫 배포가 필요함을 확인 |
