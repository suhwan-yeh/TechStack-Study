# 📚 DailyLog — 2026.11.03

## 학습 주제: Spring Security OAuth2 구글 로그인 / 로그아웃

### 1. OAuth2란?

OAuth2는 사용자가 자신의 비밀번호를 외부 애플리케이션에 제공하지 않고, 특정 리소스에 대한 접근 권한을 위임할 수 있도록 하는 인가(Authorization) 프레임워크이다.

구글 로그인에서는 OAuth2를 기반으로 한 OpenID Connect(OIDC) 또는 사용자 정보 API를 활용하여 사용자 정보를 확인하고, 애플리케이션 자체 로그인 상태를 생성할 수 있다.

**핵심 개념**
- OAuth2: 외부 서비스에 대한 접근 권한 위임
- OIDC: OAuth2 기반 사용자 인증
- Spring Security: 인증 및 인가 처리를 지원하는 보안 프레임워크
- Access Token: 보호된 API에 접근할 때 사용하는 토큰
- Authorization Code: Access Token을 발급받기 위해 교환하는 임시 코드

### 2. OAuth2 구글 로그인 동작 흐름

```text
사용자
  ↓
구글 로그인 버튼 클릭
  ↓
Spring Security OAuth2 로그인 시작
  ↓
구글 로그인 및 권한 동의
  ↓
Authorization Code 발급
  ↓
Spring Boot 서버의 콜백 URL로 전달
  ↓
서버가 Authorization Code로 토큰 요청
  ↓
구글에서 Access Token 발급
  ↓
사용자 정보 확인
  ↓
회원 조회 또는 신규 회원 등록
  ↓
Spring Security 인증 정보 생성
  ↓
로그인 완료
```

**중요한 점**

구글에서 인증받았다는 사실과 우리 서비스의 로그인 상태를 유지하는 것은 별개의 과정이다.

로그인 성공 후 우리 서버에서는 세션을 사용하거나 자체 JWT를 발급하는 방식으로 인증 상태를 유지할 수 있다.

### 3. Spring Security OAuth2 주요 구성 요소

| 구성 요소 | 역할 |
|---|---|
| SecurityFilterChain | 보안 필터 및 URL 접근 권한 설정 |
| oauth2Login() | OAuth2 로그인 기능 활성화 |
| ClientRegistration | 구글 OAuth2 클라이언트 등록 정보 |
| OAuth2UserService | OAuth2 사용자 정보 조회 및 처리 |
| OAuth2User | 인증된 사용자 정보 표현 |
| Authentication | 인증된 사용자 정보와 권한 보관 |
| SecurityContext | 현재 인증 정보 관리 |
| LogoutFilter | 로그아웃 요청 처리 |

### 4. SecurityConfig 기본 구조

```java
@Bean
public SecurityFilterChain filterChain(
        HttpSecurity http) throws Exception {

    http
        .authorizeHttpRequests(auth -> auth
            .requestMatchers("/", "/login").permitAll()
            .anyRequest().authenticated()
        )
        .oauth2Login(Customizer.withDefaults())
        .logout(logout -> logout
            .logoutSuccessUrl("/")
            .invalidateHttpSession(true)
            .clearAuthentication(true)
        );

    return http.build();
}
```

**코드 이해**

- `authorizeHttpRequests()`: URL별 접근 권한 설정
- `permitAll()`: 로그인 없이 접근 허용
- `authenticated()`: 인증된 사용자만 접근 허용
- `oauth2Login()`: OAuth2 로그인 설정
- `logout()`: 로그아웃 설정
- `invalidateHttpSession()`: HTTP 세션 무효화
- `clearAuthentication()`: 인증 정보 제거

※ 위 코드는 세션 기반 기본 예제이며, 실제 실행에는 OAuth2 클라이언트 의존성과 구글 등록 정보가 필요하다.

### 5. OAuth2 구글 로그인 설정

일반적으로 `application.yml`에 구글 OAuth2 클라이언트 정보를 설정한다.

```yaml
spring:
  security:
    oauth2:
      client:
        registration:
          google:
            client-id: ${GOOGLE_CLIENT_ID}
            client-secret: ${GOOGLE_CLIENT_SECRET}
            scope:
              - openid
              - profile
              - email
```

- `client-id`: 구글에 등록한 애플리케이션 식별자
- `client-secret`: 클라이언트 인증에 사용하는 비밀값
- `scope`: 요청하는 사용자 정보 및 권한 범위
- `redirect-uri`: 인증 완료 후 돌아올 주소

**보안 주의**

Client Secret, JWT Secret, DB 비밀번호 등은 GitHub에 직접 업로드하지 않는다. 환경변수 또는 별도의 비밀정보 관리 기능을 사용한다.

### 6. OAuth2 로그아웃

로그아웃은 현재 애플리케이션의 로그인 상태를 종료하는 과정이다.

**세션 기반 로그아웃 흐름**

```text
로그아웃 요청
  ↓
Spring Security LogoutFilter
  ↓
SecurityContext 정리
  ↓
HttpSession 무효화
  ↓
로그인 상태 종료
```

우리 서비스에서 로그아웃하더라도 구글 계정 자체의 로그인 상태는 유지될 수 있다.

또한 구글에서 발급받은 Access Token을 별도로 철회하지 않았다면 토큰이 유효할 수 있다.

### 7. OAuth2와 JWT 비교

| 구분 | OAuth2 | JWT |
|---|---|---|
| 개념 | 권한 위임 프레임워크 | 토큰 형식 |
| 목적 | 외부 서비스 접근 권한 위임 | 인증 정보 및 클레임 전달 |
| 사용 예시 | 구글 로그인 | 자체 API 인증 |
| 관계 | JWT를 토큰 형식으로 활용할 수 있음 | OAuth2 없이도 사용 가능 |

**핵심**

OAuth2와 JWT는 서로 대체하는 기술이 아니다.

구글 OAuth2 로그인 후 자체 JWT를 발급하여 API 인증에 사용하는 구조도 구현할 수 있다.

### 8. Cookie, Session과의 관계

- Cookie: 브라우저가 저장하고 요청 시 전송하는 데이터
- Session: 서버에서 사용자 상태를 유지하는 방식
- JWT: 인증 정보 등을 담는 토큰 형식
- OAuth2: 외부 서비스에 대한 권한 위임 방식

Spring Security는 OAuth2 로그인 성공 후 세션 기반으로 인증 상태를 유지할 수 있다.

JWT 기반 구조에서는 로그인 성공 시 별도의 JWT 발급 및 검증 로직을 구현할 수 있다.

### 9. 오늘 학습하며 정리한 내용

1. OAuth2는 단순한 로그인 기능이 아니라 권한 위임을 위한 프레임워크라는 것을 이해했다.
2. 구글 로그인은 Authorization Code를 이용한 토큰 교환 과정을 거친다는 것을 학습했다.
3. Spring Security가 OAuth2 인증 흐름을 처리하는 방식을 살펴보았다.
4. 로그인 성공 후 세션 또는 JWT를 통해 자체 인증 상태를 유지할 수 있음을 이해했다.
5. 우리 서비스의 로그아웃과 구글 계정 로그아웃은 서로 다르다는 것을 알게 되었다.
