# 2026-11-19 디버깅 기초 — Chrome 개발자 도구

## 오늘의 목표
Chrome 개발자 도구의 브레이크포인트를 사용해 JavaScript 실행 흐름과 변수 값의 변화를 확인한다.

## 배운 내용

### 브레이크포인트
- 코드가 특정 줄에 도달했을 때 실행을 잠시 멈추는 기능이다.
- 오류를 자동으로 찾아주는 기능은 아니다.
- 멈춘 시점의 변수 값과 호출 흐름을 살펴보고, 원인을 좁히는 데 사용한다.
- HTML 태그 줄이 아니라 실제 동작을 처리하는 JavaScript 코드에 설정해야 한다.

### Chrome 디버거 조작
- `F10`: 현재 줄을 실행하고 다음 줄로 이동한다.
- `F8`: 실행을 재개해 다음 브레이크포인트까지 진행한다.
- 노란색 줄은 다음에 실행될 코드다.
- `Scope`에서 현재 변수 값을 확인할 수 있다.
- 함수 안에서 선언하지 않은 바깥 변수는 `Local`이 아닌 `Script` 영역에 표시될 수 있다.

## 직접 확인한 내용

Chrome 디버깅 연습 파일의 방문 횟수 버튼을 눌렀다.

- 기대한 결과: 클릭할 때마다 숫자가 1씩 증가한다.
- 실제 결과: 숫자가 2씩 증가했다.
- 브레이크포인트를 `count += 2;` 줄에 설정했다.
- 실행 전 `count` 값은 `6`이었다.
- `F10`으로 해당 줄을 실행하자 `count`가 `8`로 바뀌었다.
- 다음 줄 `visitCount.textContent = count;`가 실행된 뒤 화면 숫자도 `8`로 바뀌었다.
- 코드를 확인해 클릭 한 번에 2를 더하도록 작성된 부분이 원인임을 찾았다.

## 오늘의 정리

디버깅은 문제를 재현하고, 관련 코드에서 실행을 멈춘 뒤, 한 줄씩 진행하며 변수와 화면이 어떻게 달라지는지 확인하는 과정이다.

문제가 보이는 지점이 실제 원인과 다를 수 있으므로, 기대한 결과와 실제 결과를 비교하고 값이 처음 달라지는 부분을 찾아야 한다. `console.log`로 단계와 변수 값을 남기면 문제 구간을 좁히는 데 도움이 된다.

오늘은 원인을 찾고 디버거로 확인하는 데까지 진행했다. 코드 수정 및 재실행 검증은 다음에 진행한다.
