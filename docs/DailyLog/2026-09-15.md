# 1. 파일 업로드 과정

게시판에서 사용자가 파일을 첨부해서 글을 작성한다고 생각한다.

전체적인 흐름:

사용자
→ JSP
→ Controller
→ Service
→ DAO
→ DB

단, **실제 파일과 파일 정보는 다르게 처리된다.**

### 실제 파일

실제 파일은 서버의 특정 폴더 또는 스토리지에 저장된다.

예:

`강아지.jpg`

→ 서버의 `/upload/abc123.jpg`에 저장

### DB

DB에는 파일 자체가 아니라 파일을 찾기 위한 정보를 저장한다.

예:

* 원본 파일명: `강아지.jpg`
* 저장 파일명: `abc123.jpg`
* 파일 경로: `/upload/abc123.jpg`
* 파일 크기
* 어떤 게시글의 파일인지에 대한 게시글 번호

즉,

**실제 파일 → 서버**

**파일 정보 → DB**

라고 생각하면 된다.

### FileVO

파일 정보를 `FileVO`에 담아서 이동시킬 수 있다.

`FileVO`

* originalName
* savedName
* filePath
* fileSize
* boardNo

등의 정보를 담는다.

# 2. 파일 다운로드 과정

다운로드는 업로드와 반대 방향으로 생각하면 이해하기 쉽다.

사용자가 게시글의 첨부파일을 클릭한다.

JSP
→ Controller
→ Service
→ DAO
→ DB

DB에서 해당 파일의 정보를 조회한다.

예:

게시글 번호: 10
파일명: `강아지.jpg`
저장 경로: `/upload/abc123.jpg`

이 정보를 이용해서 서버에 있는 실제 파일을 찾는다.

그 후

서버의 실제 파일
→ 사용자 PC

로 파일을 전송한다.

### 핵심

**다운로드 = DB에서 파일의 위치를 확인하고 → 서버의 실제 파일을 찾아 → 사용자에게 전송**

# 3. split()

`split()`은 문자열을 **특정 구분자를 기준으로 나누어서 배열로 만드는 것**이다.

예:

`"Java,Spring,SQL"`

에서 `,`를 기준으로 나누면

```text
Java
Spring
SQL
```

이 된다.

Java에서는:

`String[] arr = str.split(",");`

결과:

`arr[0] = "Java"`

`arr[1] = "Spring"`

`arr[2] = "SQL"`

### 기억할 것

**split = 문자열을 특정 구분자를 기준으로 잘라서 배열에 넣는다.**

예를 들어 파일명 처리에서도 문자열을 나눌 때 사용할 수 있다.

`hello.jpg`

를 `.` 기준으로 나누면

`hello`

`jpg`

처럼 분리할 수 있다.

# 4. Attribute(어트리뷰트)

Attribute는 쉽게 말하면

**"어떤 값을 저장해 놓고 다른 곳에서 꺼내 쓰기 위한 공간"**

이라고 생각하면 된다.

Servlet/JSP에서는 대표적으로

* request
* session
* application

등에 attribute를 저장할 수 있다.

예:

`request.setAttribute("name", "수환");`

그러면 request라는 공간에

```text
name → 수환
```

이라는 값을 저장한 것이다.

JSP에서는:

`${name}`

처럼 꺼내서 사용할 수 있다.

### 왜 사용하는가?

Controller에서 데이터를 가져왔는데 JSP에서 화면에 보여줘야 할 때 사용한다.

예:

```text
Controller
 ↓
DB에서 게시글 조회
 ↓
BoardVO
 ↓
request에 저장
 ↓
JSP
 ↓
화면에 출력
```

즉,

**Attribute = 데이터를 다음 처리 과정에서 사용할 수 있도록 저장해두는 공간**

이라고 이해하면 된다.

# 5. Forwarding(포워딩)

Forwarding은 **현재 요청을 다른 JSP/Servlet으로 넘기는 것**이다.

예를 들어 게시글을 조회하면:

```text
사용자
 ↓
BoardController
 ↓
게시글 조회
 ↓
request에 BoardVO 저장
 ↓
Board.jsp로 Forward
 ↓
게시글 화면 출력
```

Controller가 직접 HTML 화면을 만드는 것이 아니라,

**"이 데이터 가지고 Board.jsp에서 화면 만들어줘"**

라고 넘겨주는 것이다.

### Forward의 특징

같은 서버 내부에서 요청을 전달한다.

사용자의 요청 정보를 유지하면서 다음 페이지로 이동할 수 있다.

특히 Controller에서 데이터를 `request.setAttribute()`로 저장한 뒤 JSP로 넘길 때 자주 사용한다.

# 6. 배운 개념 하나로 연결 ㄱㄱ

게시판에서 파일이 포함된 글을 작성한다고 생각하면:

```text
사용자
 ↓
JSP
 ↓
Controller
 ↓
파일 저장
 ↓
FileVO에 파일 정보 저장
 ↓
Service
 ↓
DAO
 ↓
DB에 파일 정보 저장
```

그리고 게시글 작성이 끝난 후 결과 화면으로 이동할 때:

```text
Controller
 ↓
request.setAttribute()
 ↓
Forward
 ↓
JSP
```

이런 식으로 연결된다.

파일을 다운로드할 때는:

```text
사용자
 ↓
JSP
 ↓
Controller
 ↓
Service
 ↓
DAO
 ↓
DB에서 파일 정보 조회
 ↓
서버에서 실제 파일 찾기
 ↓
사용자에게 파일 전송
```

# 오늘의 핵심 정리

### split

**문자열을 특정 구분자로 나눠 배열로 만든다.**

### Attribute

**데이터를 저장해두고 다른 곳에서 꺼내 쓸 수 있게 한다.**

### Forward

**현재 요청을 서버 내부의 다른 JSP/Servlet으로 전달한다.**

### 파일 업로드

**실제 파일은 서버에 저장하고, 파일 정보는 DB에 저장한다.**

### 파일 다운로드

**DB에서 파일 위치를 찾고 → 서버의 실제 파일을 찾아 → 사용자에게 전송한다.**

## 오늘 느낀 점

강의를 들으면서 이미 배웠던 내용들이었지만, 막상 설명하려고 하니 `split`, Attribute, Forward 같은 개념에서 잠시 멈추게 되었다.

각 개념을 따로 외우기보다는 실제 웹 요청의 흐름 안에서 이해하는 것이 중요하다고 느꼈다.

특히 파일 업로드/다운로드는 단순히 파일을 올리고 받는 것이 아니라,

**실제 파일의 저장 + DB에 파일 정보 저장 + Controller/Service/DAO를 통한 데이터 전달**

이 함께 이루어진다는 것을 다시 정리했다.

앞으로 JSP/Servlet 게시판을 만들 때 각각의 코드가 **왜 필요한지와 어떤 역할을 하는지** 흐름을 중심으로 이해하는 것을 목표로 한다.
