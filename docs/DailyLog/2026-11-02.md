## 2. JWT란?

JWT(JSON Web Token)는 사용자에 대한 정보(Claims)를 JSON 형태로 담아 전달하는 토큰 형식이다.

로그인에 성공한 사용자에게 서버가 JWT를 발급하면, 사용자는 이후 HTTP 요청에 토큰을 포함하여 인증을 받을 수 있다.

### JWT 구조

JWT는 세 부분으로 구성된다.

`Header.Payload.Signature`

| 구성 요소 | 역할 |
|---|---|
| Header | 토큰 유형과 서명 알고리즘 |
| Payload | 사용자 식별자, 권한, 만료 시간 등의 정보 |
| Signature | 토큰의 위변조 여부를 확인하는 서명 |

JWT의 Payload는 기본적으로 암호화된 데이터가 아니므로 비밀번호와 같은 민감한 정보를 저장하면 안 된다.

---

## 3. 인증(Authentication)과 인가(Authorization)

**인증(Authentication)**

사용자가 누구인지 확인하는 과정이다.

예시: 아이디와 비밀번호를 확인하여 로그인 처리

**인가(Authorization)**

인증된 사용자가 특정 기능에 접근할 권한이 있는지 확인하는 과정이다.

예시: 일반 사용자는 관리자 페이지에 접근할 수 없도록 제한

즉, 인증은 사용자 확인이고 인가는 권한 확인이다.

---

## 4. Access Token과 Refresh Token

### Access Token

로그인 이후 보호된 API에 접근하기 위해 사용하는 토큰이다.

- 일반적으로 짧은 유효기간을 설정한다.
- HTTP 요청의 Authorization 헤더에 포함할 수 있다.
- 서버는 토큰의 서명과 만료 시간 등을 검증한다.

### Refresh Token

Access Token이 만료되었을 때 새로운 Access Token을 발급받기 위해 사용하는 토큰이다.

- 일반적으로 Access Token보다 긴 유효기간을 가진다.
- 서버에서 저장·폐기하거나 재사용을 탐지하는 정책을 적용할 수 있다.
- Refresh Token도 만료되거나 무효화되면 다시 로그인해야 한다.

Refresh Token은 반드시 JWT일 필요는 없다.

## 5. JWT 로그인 처리 흐름

일반적인 Controller 기반 JWT 로그인 구조

```text
사용자
  ↓
POST /login
  ↓
Spring Security Filter Chain
  ↓
AuthController
  ↓
AuthService
  ↓
사용자 정보 및 비밀번호 검증
  ↓
TokenProvider
  ↓
JWT 생성
  ↓
클라이언트에 토큰 응답
```

### 단계별 설명

1. 사용자가 아이디와 비밀번호를 입력한다.
2. 클라이언트가 서버에 POST 로그인 요청을 전송한다.
3. Spring Security의 필터 체인을 거친다.
4. 인증 서비스에서 사용자 정보와 비밀번호를 검증한다.
5. 인증에 성공하면 TokenProvider를 통해 JWT를 생성한다.
6. 클라이언트가 발급된 토큰을 이후 요청에 사용한다.

비밀번호는 평문으로 비교하거나 저장하지 않고, 안전한 비밀번호 해싱 방식을 사용해야 한다.

※ 로그인 요청 자체를 Spring Security의 인증 필터에서 처리하는 구현도 존재한다.

## 6. JWT Filter란?

Filter는 HTTP 요청이 Controller에 전달되기 전에 실행될 수 있는 구성 요소이다.

JWT 인증 필터는 HTTP 요청에서 JWT를 추출하고, 유효성을 검사하여 인증 정보를 설정하는 역할을 한다.

### JWT 인증 처리 흐름

```text
클라이언트
  ↓
HTTP 요청 + JWT
  ↓
JWT Authentication Filter
  ↓
Authorization 헤더에서 토큰 추출
  ↓
TokenProvider로 JWT 검증
  ↓
Authentication 객체 생성
  ↓
SecurityContext에 인증 정보 설정
  ↓
Spring Security 인가 검사
  ↓
Controller
  ↓
Service
  ↓
Repository
  ↓
DB
```

JWT가 유효하더라도 요청한 기능에 접근할 권한이 없다면 인가 과정에서 거부될 수 있다.

### OncePerRequestFilter

Spring Security에서 JWT 인증 필터를 만들 때 자주 사용하는 클래스이다.

일반적인 요청 처리 과정에서 필터가 중복 실행되는 것을 방지하도록 설계되어 있다.

---

## 7. TokenProvider란?

TokenProvider는 JWT 생성, 검증, 정보 추출 기능을 담당하는 클래스이다.

주요 역할은 다음과 같다.

| 메서드 예시 | 역할 |
|---|---|
| `createToken()` | JWT 생성 |
| `validateToken()` | 서명 및 만료 시간 등 검증 |
| `getAuthentication()` | 토큰을 바탕으로 인증 정보 생성 |
| `getUsername()` | 토큰에서 사용자 식별자 추출 |

TokenProvider는 Spring Security가 반드시 제공하는 표준 클래스 이름이 아니라 개발자가 정의하는 클래스인 경우가 많다.

**Filter와 TokenProvider의 차이**

- Filter: HTTP 요청에서 토큰을 추출하고 인증 과정을 진행
- TokenProvider: JWT 자체를 생성하거나 검증하는 기능 제공

## 8. Authorization 헤더와 Bearer

JWT를 사용하는 API 요청 예시

```http
GET /api/mypage
Authorization: Bearer eyJhbGciOiJIUzI1Ni...
```

- Authorization: HTTP 인증 정보를 전달하는 헤더
- Bearer: 토큰 기반 인증 스킴
- 뒤의 문자열: 실제 Access Token

### Java에서 토큰 추출

```java
String header = request.getHeader("Authorization");

if (header != null && header.startsWith("Bearer ")) {
    String token = header.substring(7);
}
```

`Bearer`는 6글자이며 뒤에 공백이 1글자 있다.

따라서 `substring(7)`을 사용하면 7번 인덱스부터 문자열 끝까지 가져와 실제 토큰 값만 추출할 수 있다.

`Bearer` 뒤에는 JWT뿐 아니라 다른 형식의 Access Token도 올 수 있다.

---

## 9. SecurityContextHolder란?

SecurityContextHolder는 Spring Security에서 현재 실행 흐름의 인증 정보를 관리하는 기능을 제공한다.

JWT 인증 필터에서 유효한 토큰을 확인하면 Authentication 객체를 생성하고 SecurityContext에 설정할 수 있다.

```java
SecurityContextHolder.getContext()
    .setAuthentication(authentication);
```

이후 Controller 등에서 현재 인증된 사용자 정보를 활용할 수 있다.

일반적인 JWT 기반 Stateless 인증에서는 요청마다 토큰을 검증하고 인증 정보를 새로 설정한다.

## 10. JWT 로그아웃 처리

JWT 로그아웃에서 가장 중요한 점은 클라이언트가 토큰을 삭제하더라도 이미 발급된 JWT가 자동으로 무효화되지는 않는다는 것이다.

### 로그아웃 처리 방식

**1. 클라이언트 토큰 삭제**

브라우저에 보관된 인증 정보를 제거한다.

하지만 탈취된 Access Token이 있다면 만료 전까지 사용될 가능성이 있다.

**2. Refresh Token 무효화**

서버가 관리하는 Refresh Token을 삭제하거나 폐기하여 새로운 Access Token 발급을 차단한다.

**3. Access Token 차단 목록**

즉시 무효화가 필요한 경우 Redis 등에 토큰 식별자를 저장하여 만료 전에도 사용하지 못하도록 할 수 있다.

따라서 JWT 로그아웃은 서비스의 보안 요구사항에 따라 설계해야 한다.

## 11. 주요 클래스 역할 정리

| 클래스 | 주요 역할 |
|---|---|
| SecurityConfig | Spring Security 보안 정책과 필터 체인 설정 |
| SecurityFilterChain | HTTP 요청에 적용할 보안 필터 구성 |
| JwtAuthenticationFilter | 요청에서 JWT 추출 및 인증 처리 |
| TokenProvider | JWT 생성, 검증, 정보 추출 |
| AuthController | 로그인·로그아웃 API 요청 처리 |
| AuthService | 로그인 및 로그아웃 비즈니스 로직 |
| AuthenticationManager | 사용자 인증 처리 |
| SecurityContextHolder | 현재 인증 정보 관리 |

실제 프로젝트에 따라 클래스명과 책임은 달라질 수 있다.

---

## 12. 오늘 이해한 핵심

1. JWT는 인증 정보를 전달하는 토큰 형식이다.
2. 로그인에 성공하면 서버에서 JWT를 발급할 수 있다.
3. 로그인 이후 클라이언트는 Access Token을 HTTP 요청에 포함한다.
4. JWT Filter는 Controller보다 앞에서 토큰 인증을 처리한다.
5. TokenProvider는 JWT 생성 및 검증 기능을 담당한다.
6. SecurityContextHolder는 현재 인증 정보를 관리한다.
7. 로그아웃 시 클라이언트 토큰 삭제만으로 서버의 JWT가 무효화되지는 않는다.
8. Refresh Token을 활용하면 Access Token 만료 후 재발급할 수 있다.
