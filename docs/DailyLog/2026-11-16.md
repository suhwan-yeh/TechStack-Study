# Daily Log — 2026.11.16

## 오늘 공부한 내용

### 1. 정규식과 자바 코드로 문자열 처리하기
- 정규식은 문자열에서 특정한 패턴을 찾거나 바꿀 때 사용하는 표현식이다.
- `replaceAll(정규식, 바꿀 문자열)`로 원하는 부분을 치환할 수 있다.
- Java 문자열 안에서 정규식의 `\d`는 `\\d`로 작성한다.
- 정규식 대신 `substring()`, `repeat()` 등의 자바 코드로도 마스킹을 구현할 수 있다.

### 2. 마스킹
- 개인정보의 일부를 `*` 등으로 가리는 처리이다.
- 전화번호: `010-1234-5678` → `010-****-5678`
- 이름: `홍길동` → `홍*동`
- DB 원본을 변경하지 않고, 화면에 전달하는 DTO를 만들 때 마스킹할 수 있다.

### 3. ORM
- ORM(Object-Relational Mapping)은 객체와 관계형 DB의 테이블을 연결하는 기술이다.
- 자바 객체를 저장하거나 조회하면 ORM이 필요한 SQL을 생성하고 실행한다.
- SQL 작성이 줄어들지만, 실행되는 쿼리를 확인하지 않으면 N+1 같은 성능 문제가 생길 수 있다.

### 4. 인터페이스
- 클래스가 어떤 기능을 제공해야 하는지 정하는 규약이다.
- 구현 클래스는 인터페이스에 선언된 메서드를 구현한다.
- 호출하는 쪽이 구체적인 구현에 덜 의존하게 만들어 구현 교체와 테스트에 도움이 된다.

### 5. JPA와 Hibernate
- JPA는 자바에서 ORM을 사용하기 위한 표준 명세이다.
- Hibernate는 JPA를 구현한 대표적인 ORM 프레임워크이다.
- 엔티티 매핑, SQL 생성, 변경 감지, 지연 로딩 등의 기능을 제공한다.

### 6. 트랜잭션
- 여러 DB 작업을 하나의 작업 단위로 묶는 개념이다.
- 성공하면 커밋하고, 실패하면 롤백하여 데이터의 일관성을 유지한다.
- Spring에서는 `@Transactional`로 트랜잭션 범위를 지정할 수 있다.
- LAZY 연관 데이터에 접근할 때는 영속성 컨텍스트가 유지되는 범위를 고려해야 한다.

### Mission 6 — 고객 전화번호 마스킹 성공
- 문제: 고객 목록에 전화번호 원문이 그대로 노출되었다.
- 원인: `CustomerService.toView()`에서 전화번호를 가공 없이 DTO에 전달했다.
- 해결: DTO로 변환하는 단계에서 전화번호 가운데 자리를 가리도록 처리했다.
- 결과: 전화번호 마스킹 테스트 통과.

### Mission 1 — 맛집 목록 N+1 개선 성공
- 문제: 맛집 목록에서 리뷰 개수를 구할 때 추가 SQL이 반복 실행되었다.
- 원인: 반복문에서 `store.getReviews().size()`를 호출하면서 지연 로딩이 발생했다.
- 해결: DTO 프로젝션과 `LEFT JOIN`, `GROUP BY`, `COUNT`로 필요한 정보와 리뷰 개수를 한 번에 조회했다.
- 결과: 맛집 목록을 SQL 1회로 조회하는 테스트 통과.
